# О пакетах Ubuntu, APT и dpkg

> Статус: актуален
> Обновлено: 2026-11-05 09:50 MSK
> Ответственный: Codex

## 1. Общая идея

**APT и dpkg — два уровня одной системы управления пакетами Ubuntu.**
APT организует поиск, получение и подбор зависимостей.
dpkg устанавливает пакеты и ведёт сведения об их состоянии.

Оба инструмента работают на локальной машине.
Разделение на «APT для удалённых пакетов, dpkg для локальных»
неточно: APT умеет устанавливать и локальные файлы.

В Avalon мы использовали их для установки и диагностики Docker.
PostgreSQL и Superset затем запустили в контейнерах:
это другой уровень доставки программ.

Команда `apt` позволяет устанавливать, обновлять и удалять пакеты,
а также получать сведения о них.

При установке APT определяет зависимости и получает нужные пакеты.
Непосредственную установку файлов пакетов выполняет механизм dpkg.

## 2. Что такое пакет Ubuntu

В данном контексте пакет — установочный комплект формата .deb.
Он может содержать приложение, библиотеку, документацию или системный компонент.

Внутри находятся:
- файлы программы для размещения в системе;
- метаданные: имя, версия, архитектура;
- зависимости и ограничения совместимости;
- при необходимости служебные скрипты установки и удаления.

Одна программа может состоять из нескольких пакетов.
Например, Docker Engine, клиент Docker и плагин Compose устанавливаются
отдельными пакетами.

| Объект | Пример |
|---|---|
| Пакет | docker-ce-cli |
| Файл исполняемой программы | /usr/bin/docker |
| Команда пользователя | docker |
| Служба | docker.service |
| Контейнер приложения | superset_app |

Название пакета не обязано совпадать с названием команды.
Установка пакета также не доказывает работоспособность службы.

### Просмотр .deb без установки

Если доверенный файл уже скачан:

```bash
dpkg-deb --info ./program.deb
dpkg-deb --contents ./program.deb
```

Первая команда показывает информацию о пакете, вторая — его файлы.
program.deb — условное имя, его нужно заменить фактическим.
Простая распаковка не равна установке: не выполняется полный учёт
и настройка пакета.
[Справочник dpkg-deb](https://manpages.debian.org/trixie/dpkg/dpkg-deb.1.en.html).

## 3. Зависимости

Программа может требовать другие библиотеки или компоненты.
В пакете это описано как зависимости.

При установке нельзя произвольно собрать любые версии:
их требования должны быть совместимы.
APT составляет план изменений с учётом этих требований.
Если подходящего плана нет, установка может быть остановлена.

В нашем случае вместе с явно указанными компонентами Docker
APT установил дополнительные пакеты. Поэтому количество
установленных пакетов оказалось больше числа имён в команде.

## 4. Удалённый репозиторий

Репозиторий пакетов — источник, в котором размещаются:
- установочные .deb-файлы;
- индексы с доступными версиями и зависимостями;
- метаданные и подписи для проверки получаемых материалов.

Обычно это удалённый сервер, но источники могут быть и локальными.
На Ubuntu одновременно подключаются несколько репозиториев:
основной архив, обновления безопасности, источник Docker и другие.

### Что означает «добавить репозиторий Docker»

Мы записываем источник в настройки APT на рабочей Ubuntu,
а не копируем весь удалённый репозиторий на ВМ.

Для нашего стенда файл источника:

```text
/etc/apt/sources.list.d/docker.sources
```

В нём указаны адрес `https://download.docker.com/linux/ubuntu`,
выпуск `resolute`, компонент `stable`, архитектура `amd64`
и путь к публичному ключу проверки подписи.

Источники APT могут задаваться также в `/etc/apt/sources.list`
и других файлах `/etc/apt/sources.list.d/`.
Одна команда обновления обращается к настроенным источникам,
а не только к Docker.


### Для чего нужен локальный список пакетов

APT хранит локальную копию индексов, обычно в `/var/lib/apt/lists/`.
По ним он определяет:
- какие пакеты доступны и в каких версиях;
- какие зависимости потребуются;
- откуда скачать пакет;
- есть ли доступная версия новее установленной.

Это сведения о доступных пакетах, а не сами установочные файлы.
Состояние уже установленных пакетов хранится отдельно в базе dpkg.

## 5. Что такое APT

APT — Advanced Package Tool, набор инструментов и библиотек
управления пакетами. Команда apt — интерфейс для повседневной работы.

APT:
1. Читает индексы источников и состояние установленных пакетов.
2. Подбирает версии и зависимости.
3. Показывает план изменений.
4. Скачивает нужные пакеты.
5. Использует dpkg для установки и настройки.

APT работает с настроенными источниками, а не ищет программу
произвольно во всём интернете.
[Справочник apt](https://manpages.ubuntu.com/manpages/resolute/man8/apt.8.html).

### Обновление индексов: apt update

```bash
sudo apt update
```

```bash
sudo apt update
```

Команда получает актуальные индексы и метаданные из настроенных
удалённых репозиториев, проверяет их подписи и обновляет локальные
списки. Неизменившиеся индексы не обязательно скачиваются заново.

`sudo` нужен для записи в системные каталоги APT.

```text
Удалённые репозитории Ubuntu и Docker
                  ↓
          sudo apt update
                  ↓
Локальные списки доступных пакетов на рабочей ВМ
                  ↓
     sudo apt install <имя-пакета>
                  ↓
       Скачивание и установка пакета
```

**Важно:** `apt update` не устанавливает новые программы
и не обновляет установленные. Он обновляет сведения об их доступности.

После добавления нового источника выполняем `apt update`,
чтобы APT узнал о его пакетах.

### Установка пакета

```bash
sudo apt install curl
```

APT найдёт пакет и необходимые зависимости.
Уже установленный пакет может быть обновлён до выбранной версии.

### Информационные команды

```bash
apt search docker
apt show docker-ce
apt list --upgradable
```

Соответственно: поиск, описание пакета и список доступных обновлений.
Обычно sudo для этих запросов не нужен.

### update и upgrade

- update — обновление сведений о пакетах.
- upgrade — обновление установленных программ.
- full-upgrade — обновление с возможностью удаления пакетов
  для разрешения зависимостей.

apt upgrade может установить новые зависимости, но не удаляет
существующие пакеты ради обновления.
Общее обновление системы — отдельная операция,
а не обязательное продолжение каждого update.

### apt и apt-get

Оба относятся к APT. apt ориентирован на интерактивную работу,
apt-get чаще используют в сценариях автоматизации.
Некоторые детали поведения различаются: нельзя считать
все одноимённые команды полностью взаимозаменяемыми.

Локальная справка:

```bash
man apt
man apt-get
```

Из просмотрщика обычно выходят клавишей q.

## 7. Что такое dpkg

dpkg — базовый менеджер пакетов Debian, который используется Ubuntu.

Он непосредственно:
- распаковывает пакет;
- выполняет настройку и служебные скрипты;
- регистрирует установленную версию и состояние;
- удаляет пакет по команде пользователя.

Пример установки:

```bash
sudo dpkg -i ./program.deb
```

-i означает install. Нужен уже имеющийся локальный файл.
Если зависимостей не хватает, dpkg сам не подбирает
и не скачивает их из репозитория.

Пакет может остаться распакованным, но не настроенным.
Поэтому наличие его файлов ещё не подтверждает успешную установку.
[Справочник dpkg](https://manpages.debian.org/trixie/dpkg/dpkg.1.en.html).

### Зачем пользоваться APT, если есть dpkg

APT снимает с пользователя большую часть работы по поиску версий
и получению зависимостей. Обычно установку выполняют через APT,
а dpkg используют для диагностики и специальных операций.

APT также умеет установить локальный файл:

```bash
sudo apt install ./program.deb
```

Он попытается получить недостающие зависимости из настроенных источников.
Префикс ./ указывает на файл в текущем каталоге.
Нельзя считать произвольный скачанный файл безопасным
только потому, что для установки используется APT.

## 8. Что такое dpkg-query

dpkg-query — инструмент чтения базы dpkg.
Он показывает сведения о пакетах, их состоянии и зарегистрированных файлах.

### Версия и статус

```bash
dpkg-query -W -f='${binary:Package}\t${Status}\t${Version}\n' docker-ce
```

- -W — запросить сведения.
- -f — указать формат вывода.
- binary:Package — название пакета.
- Status — состояние.
- Version — версия.
- \t — табуляция; \n — новая строка.

Одинарные кавычки сохраняют шаблон для dpkg-query:
оболочка не подставляет значения вместо ${...}.

Статус install ok installed означает установленный пакет.
unknown ok not-installed — пакет не установлен.
Именно такие строки мы видели у некоторых имён PostgreSQL
при первоначальной диагностике.

### Поиск группы пакетов

```bash
dpkg-query -W 'docker*' 'containerd*'
```

Кавычки защищают шаблоны от раскрытия оболочкой.
Само имя в выводе не означает установку — проверяем статус.

### Принадлежность файла

```bash
dpkg-query -L docker-ce-cli
dpkg-query -S /usr/bin/docker
```

-L — зарегистрированные файлы пакета.
-S — поиск пакета по пути.
Это чтение базы, а не проверка наличия всех файлов на диске.
[Справочник dpkg-query](https://manpages.debian.org/trixie/dpkg/dpkg-query.1.en.html).

## 9. Архитектура пакетов

```bash
dpkg --print-architecture
```

На рабочем стенде команда вернула amd64.
Это основная архитектура пакетов системы, соответствующая
64-битной x86, а не указание производителя процессора.

| Обозначение | Значение |
|---|---|
| amd64 | 64-битная x86, также x86_64 |
| i386 | 32-битная x86 |
| arm64 | 64-битная ARM |
| all | Пакет не привязан к одной архитектуре |

Сборки под разные архитектуры обычно содержат разный машинный код.
Прямой запуск arm64-программы на amd64 обычно невозможен
без дополнительных средств.

Архитектура — не единственное условие совместимости:
важны выпуск Ubuntu, библиотеки и их версии.

## 10. Как APT и dpkg работают вместе

```text
Пользователь: sudo apt install docker-ce
                     ↓
APT читает индексы источников и состояние системы
                     ↓
Подбирает версии и зависимости, показывает план
                     ↓
Скачивает .deb-файлы
                     ↓
dpkg распаковывает и настраивает пакеты
                     ↓
Состояние сохраняется в базе dpkg
                     ↓
Пользователь проверяет работу Docker
```

Успех установки и работоспособность приложения — отдельные проверки.
При конфликте зависимостей APT может не найти допустимый план.
Не выполнять автоматически предложенные удаления,
не разобрав их последствия.
[Справочник apt-get](https://manpages.debian.org/trixie/apt/apt-get.8.en.html).

### Таблица различий

| Возможность | APT | dpkg |
|---|---|---|
| Получать индексы источников | Да | Нет |
| Скачивать пакеты из репозиториев | Да | Нет |
| Подбирать зависимости | Да | Проверяет требования, но не скачивает зависимости |
| Устанавливать локальный .deb | Да, через dpkg | Да |
| Распаковывать и настраивать пакет | Организует через dpkg | Выполняет |
| Учитывать установленные пакеты | Использует базу dpkg | Ведёт базу |
| Обновлять по версиям из источников | Организует | Требуется соответствующий локальный файл |

Работа без интернета возможна при наличии нужных архивов
и зависимостей; это не уникальная возможность dpkg.

## 11. Публичный ключ и проверка источника

APT проверяет подпись метаданных репозитория публичным ключом,
затем проверяет пакеты по связанным контрольным суммам.

Издатель хранит приватный ключ и подписывает материалы.
Публичный ключ распространяется открыто и служит для проверки,
а не для входа в аккаунт или шифрования загрузки.

Для Docker использовался файл /etc/apt/keyrings/docker.asc,
указанный через Signed-By в docker.sources.

Подпись подтверждает происхождение и целостность,
но не гарантирует отсутствие ошибок в программе.
[Справочник apt-secure](https://manpages.debian.org/trixie/apt/apt-secure.8.en.html).

## 12. Как это использовалось в Avalon

На рабочей ВМ пользователь добавил источник Docker,
обновил индексы и установил:

```bash
sudo apt update
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

30 октября 2026 года установились Docker 29.9.2, Compose 5.6.1,
containerd 2.4.2 и Buildx 0.38.1.
Это исторический результат, а не гарантия версий при повторе команды.

После установки проверили службу Docker и запуск hello-world.

PostgreSQL и Superset запущены контейнерами:

```text
APT и dpkg на Ubuntu → Docker Engine
                            ↓
                    образы и контейнеры
                            ↓
                   PostgreSQL и Superset
```

Поэтому отсутствие пакета PostgreSQL в базе dpkg хоста
не доказывает отсутствие работающей базы в Docker.

Для повторения стенда нужны и версии хостового ПО,
и Compose-файлы, образы, локальные настройки и хранилища.

## 13. Памятка

| Задача | Инструмент |
|---|---|
| Узнать архитектуру | dpkg --print-architecture |
| Проверить установленный пакет | dpkg-query -W |
| Найти пакет | apt search |
| Обновить индексы | sudo apt update |
| Установить пакет по имени | sudo apt install имя |
| Установить доверенный локальный файл с подбором зависимостей | sudo apt install ./файл.deb |
| Изучить .deb без установки | dpkg-deb --info ./файл.deb |
| Проверить контейнерные приложения | Docker и Compose |

Примеры изменяющих команд в этом документе приведены для обучения.
При создании файла установка, удаление и обновление ПО не выполнялись.
Ранее выполненные действия проекта описаны отдельно в разделе 12.
