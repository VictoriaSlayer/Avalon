# Вопрос №1. Полная статусная модель.
Нужно для расчёта интервалов между статусами
# Ответ №1.
## Статусная модель
В первой итерации разработки отчета ориентируемся на следующие статусы:
Проект - документ зарегистрирован в системе.
На согласовании - документ отправлен на согласование.
Согласован - документ согласован.
Не согласован - документ не согласован.

## Как отбираем события

Историю рассматриваем отдельно для каждого документа в порядке возрастания
поля «Период». Для связи записей используем идентификатор документа;
конкретное поле определим на этапе описания данных.

- Регистрация документа — самая ранняя запись со статусом «Проект».
- Для построения циклов используем события «На согласовании», «Согласован»
  и «Не согласован», у которых значение «Установил» начинается с `Согласование "`.
- Циклы нумеруем по времени начала внутри одного документа.
  Результаты «Согласован» и «Не согласован» отдельно не нумеруем
  для сопоставления с началами циклов.

**Предположение:** два последовательных события «На согласовании» невозможны;
у событий одного документа разное время. При обнаружении нарушения этих
условий случай требует разбора, а не автоматического сопоставления событий.

# Вопрос №3. Как считаем

## 3.1. Рабочее время

Длительности считаем в рабочих часах по официальному производственному
календарю, который будет выгружен в отдельную таблицу. Для интервала между
двумя событиями учитываем только время, попавшее в рабочие интервалы календаря.
Неполные рабочие часы учитываем как долю часа; нерабочее время исключаем.

Рабочие интервалы внутри дня, перерывы, часовой пояс и состав полей
таблицы уточним при подготовке рабочего календаря. По решению пользователя
это обсуждение отложено до работы с календарём.

## 3.2. Единое правило цикла согласования

1. Событие «На согласовании» открывает новый цикл документа.
2. Следующее по времени событие «Согласован» или «Не согласован» закрывает
   этот цикл и определяет его результат.
3. Следующее событие «На согласовании» открывает следующий цикл того же
   документа. Циклы считаются и после отказа, и после успешного согласования.
4. Если после начала ещё нет результата, цикл остаётся открытым.
5. Длительность завершённого цикла — рабочее время от его начала до его
   результата. Период доработки между циклами в эту длительность не входит.

**Важно:** начало и результат связываем по последовательности событий,
а не по порядковому номеру статуса каждого вида. Первый статус «Согласован»
может завершать второй или последующий цикл.

**Пример — синтетические данные:** в таблице выше:

| Цикл | Начало | Завершение | Результат |
| --- | --- | --- | --- |
| 1 | 02.10.2026 11:47:28 | 02.10.2026 13:01:59 | Не согласован |
| 2 | 05.10.2026 15:47:12 | 05.10.2026 15:59:38 | Согласован |

Здесь два начатых и два завершённых цикла: один успешный и один неуспешный.
Рабочее время между отказом первого цикла и началом второго учитывается
отдельно как время между циклами.

## 3.3. Количество циклов и количество документов

Это разные показатели:

- Начатые циклы — количество событий начала цикла.
- Завершённые успешные циклы — количество циклов с результатом «Согласован».
- Завершённые неуспешные циклы — количество циклов с результатом «Не согласован».
- Открытые циклы — начатые циклы, у которых ещё нет результата.

Документы считаем отдельно по текущему статусу, каждый документ — один раз
в соответствующей группе:

- «Согласован» — количество документов с текущим статусом «Согласован».
- «Не согласован» — количество документов с текущим статусом «Не согласован».
- «На согласовании» — отдельное количество документов, согласование которых
  сейчас продолжается.

Документы в статусе «Проект» не относятся ни к одной из этих трёх групп.
Документ, который сначала не согласовали, а затем согласовали, учитывается
в текущей группе «Согласован». Его предыдущий отказ сохраняется в истории
и учитывается в количестве неуспешных циклов.

Текущий статус определяем по последней записи всей истории документа
(максимальное значение «Период») без фильтра по «Установил».
Если после отказа сотрудник вручную установил «Проект», текущий статус —
«Проект». Фильтр по «Установил» применяется только при построении циклов
согласования, а не при определении текущего статуса.

## 3.4. Общее время до согласования

Для документа, имеющего событие «Согласован», общее время — рабочие часы
от самого раннего начала согласования до последнего события «Согласован».
В отличие от длительности отдельного цикла, этот интервал включает рабочее
время между циклами, в том числе доработки.

Для документа без события «Согласован» данная метрика не определена:
успешное согласование ещё не зафиксировано. Такие документы учитываем
отдельно по текущим статусам; время до текущего момента не подставляем
в формулу завершённого согласования.

**Открытый вопрос:** нужны ли отдельные длительности для документов,
которые сейчас «Не согласован» или «На согласовании»? Правила их расчёта
пока не согласованы.

# Вопрос №4. Окончательно отклонённые документы

В 1С ДО отсутствует признак, позволяющий отличить окончательный отказ
от отказа с возможной дальнейшей доработкой. Поэтому считаем документы
по текущим статусам и циклы по результатам. Статус «Не согласован»
сам по себе не означает окончательного прекращения работы.
