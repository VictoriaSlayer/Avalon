
| Что получить                | Какие сведения нужны                                                                                                                                      |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. Версии ПО**            | Ubuntu, Docker Engine, Docker Compose, фактические образы PostgreSQL и Superset: теги и желательно digest                                                 |
| **2. Конфигурация запуска** | Используемые Compose-файлы, Dockerfile, дополнительные конфигурационные файлы; команды запуска и первоначальной настройки                                 |
| **3. Переменные окружения** | `.env.example`: имена переменных, безопасные значения и заглушки вместо секретов. Какие значения обязательны и где используются                           |
| **4. Хранение данных**      | Для каждого сервиса: Docker volume или каталог Ubuntu, путь внутри контейнера; какие данные нужно сохранять между перезапусками                           |
| **5. Сети и порты**         | Docker-сети, взаимодействие контейнеров, опубликованные порты и адреса привязки                                                                           |
| **6. PostgreSQL**           | Название учебной базы, роли и необходимые права, схемы, расширения, кодировка, часовой пояс; скрипты инициализации без паролей                            |
| **7. Superset**             | Пользовательские настройки, установленные драйверы подключения к PostgreSQL, дополнительные зависимости; назначение служебной базы, Redis и workers       |
| **8. Настройки Ubuntu**     | Изменения Docker и systemd, необходимые права на каталоги, зависимость запуска от `/data`. Отметить, какие настройки нужны только из-за домашней разметки |
| **9. Проверки**             | Что фактически проверено: запуск, вход в Superset, подключение к PostgreSQL, график на синтетических данных, работа после перезапуска                     |
**На выходе лучше получить:**
```
infrastructure/
├── compose.yaml           # Или несколько фактически используемых файлов
├── .env.example
└── superset/
    └── superset_config.py # Если используется

technical/
└── home-stand.md          # Версии, хранение, запуск и результаты проверок
```
Если конфигурация пока разбросана по разным каталогам, сначала достаточно **перечня файлов и их назначения**. Перестраивать домашний стенд ради сбора информации не нужно.

**Передавать не нужно:** настоящие `.env`, пароли, ключи, дампы баз, корпоративные выгрузки, содержимое Docker volumes и файлы самой базы PostgreSQL. На рабочем стенде зададим собственные секреты.

DBeaver — отдельный клиент на твоём компьютере; для работы серверной части устанавливать его на ВМ не требуется.
